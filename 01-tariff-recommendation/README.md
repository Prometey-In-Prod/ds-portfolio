# Рекомендация тарифов

Оператор мобильной связи хочет предлагать клиентам с архивных тарифов
один из двух актуальных — «Смарт» или «Ультра». Задача: по поведению
клиента за месяц предсказать, какой тариф ему подходит.

Задача бинарной классификации. Требование заказчика — доля правильных
ответов не ниже 0,75 на отложенной выборке.

## Данные

3214 клиентов, по каждому — поведение за один месяц:

| признак | описание |
|---|---|
| `calls` | количество звонков |
| `minutes` | суммарная длительность звонков, мин |
| `messages` | количество sms |
| `mb_used` | израсходованный интернет-трафик, Мб |
| `is_ultra` | целевой признак: 1 — «Ультра», 0 — «Смарт» |

Данные предоставлены курсом «Специалист по Data Science» Яндекс.Практикума
в учебных целях.

Пропусков и дубликатов нет. Классы распределены неравномерно: **69% «Смарт»,
31% «Ультра»** — это определило всю дальнейшую методику оценки.

## Что сделано

1. **Посчитан базовый уровень до обучения моделей.** Константная модель,
   отвечающая всем «Смарт», даёт accuracy 0,694. Без этой точки отсчёта
   любое значение метрики невозможно интерпретировать.
2. **Данные разделены на три части 60/20/20** со стратификацией по целевому
   признаку.
3. **Гиперпараметры подбирались только на валидационной выборке** — решающее
   дерево, случайный лес и логистическая регрессия (со стандартизацией
   признаков в `Pipeline`).
4. **Тестовая выборка использована один раз**, после того как модель была
   окончательно выбрана и переобучена на обучающей плюс валидационной.

## Результаты

Валидационная выборка, 643 объекта:

| модель | гиперпараметры | accuracy | над константой |
|---|---|---:|---:|
| базовый уровень | всегда «Смарт» | 0,694 | — |
| логистическая регрессия | `Pipeline(StandardScaler, LogisticRegression)` | 0,737 | +4,4 п.п. |
| решающее дерево | `max_depth=3` | 0,799 | +10,6 п.п. |
| **случайный лес** | `n_estimators=30, max_depth=6` | **0,820** | **+12,6 п.п.** |

**Тестовая выборка (один замер): accuracy 0,818** при базовом уровне 0,694 —
выигрыш **12,4 процентных пункта**. Порог 0,75 пройден. Расхождение
с валидационной оценкой — 0,2 п.п. при стандартной ошибке около 1,6 п.п.,
то есть результат воспроизвёлся.

## Выводы

**Метрика без точки отсчёта бессодержательна.** При перекосе классов 69/31
accuracy 0,74 у логистической регрессии выглядит приемлемо, но модель нашла
лишь **35 пользователей «Ультра» из 197** (recall 0,18): она относит к
редкому классу только клиентов с экстремальными показателями, а всех
сомнительных — к большинству. Её результат держится почти целиком на том,
что «всегда отвечать Смарт» на таких данных и есть выигрышная по accuracy
стратегия.

**Почему деревья справились, а линейная модель нет.** Логистическая регрессия
проводит одну прямую границу между классами; в этих четырёх признаках классы
так не разделяются. Дерево и лес строят границу из множества условий и
улавливают сочетания признаков, недоступные линейной модели.

**Различия в третьем знаке — шум.** Несколько конфигураций леса дали результат
в пределах 0,3 п.п. при стандартной ошибке 1,6 п.п. Из этой группы выбрана
самая экономная по вычислениям, а не формальный максимум.

## Ограничения

- Accuracy не различает типы ошибок: предложить «Смарт» тому, кому нужен
  «Ультра», и наоборот — разные потери для оператора. Перед внедрением нужна
  метрика, учитывающая цену каждой ошибки.
- Признаков всего четыре, и они сильно связаны между собой (звонки и минуты
  описывают почти одно и то же). Потолок качества на таких данных невысок.
- Модель предсказывает, каким тарифом клиент пользуется. Бизнес-вопрос
  другой: какой тариф ему **выгоднее** предложить. Для второй задачи нужны
  данные о ценах тарифов и фактических платежах.
