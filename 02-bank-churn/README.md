# Отток клиентов банка

«Бета-Банк» теряет клиентов — немного, но каждый месяц. Маркетологи
посчитали, что удерживать текущего клиента дешевле, чем привлекать нового.
Задача: по историческим данным о поведении клиента предсказать, уйдёт ли он
из банка в ближайшее время, чтобы кампания удержания работала адресно.

Задача бинарной классификации с перекосом классов. Требование заказчика —
**F1-мера не ниже 0,59** на отложенной выборке. Дополнительно измеряется
AUC-ROC.

## Данные

10 000 клиентов, по каждому — профиль и признаки поведения:

| признак | описание |
|---|---|
| `CreditScore` | кредитный рейтинг |
| `Geography` | страна проживания (Франция, Германия, Испания) |
| `Gender` | пол |
| `Age` | возраст |
| `Tenure` | сколько лет человек является клиентом банка |
| `Balance` | баланс на счёте |
| `NumOfProducts` | количество используемых продуктов банка |
| `HasCrCard` | наличие кредитной карты |
| `IsActiveMember` | активность клиента |
| `EstimatedSalary` | предполагаемая зарплата |
| `Exited` | целевой признак: 1 — клиент ушёл |

Данные предоставлены курсом «Специалист по Data Science» Яндекс.Практикума
в учебных целях.

Классы распределены неравномерно: **20,4% ушедших против 79,6% оставшихся**,
отношение 1:3,9. Полных дубликатов нет.

### Что видно в данных до обучения

**Пропуски — только в `Tenure`, 9,1%.** Перед выбором способа заполнения
проверено, информативен ли сам факт пропуска: доля ушедших среди клиентов
с пропуском 0,201 против 0,204 среди остальных. Доли совпадают, значит
пропуск ничего не кодирует и заполнение медианой не затирает сигнал.

**Зависимость оттока от числа продуктов немонотонна и разворачивается:**

| продуктов | клиентов | доля ушедших |
|---:|---:|---:|
| 1 | 5084 | 27,7% |
| 2 | 4590 | 7,6% |
| 3 | 266 | 82,7% |
| 4 | 60 | 100% |

Минимум оттока — у клиентов с двумя продуктами, дальше он взлетает. Линейная
модель обязана провести через эти точки монотонную зависимость, а они её не
допускают, поэтому `NumOfProducts` закодирован как категориальный признак,
а не как число.

**Распределение баланса двугорбое:** у 3617 клиентов (36%) баланс ровно
нулевой, остальные образуют почти нормальное облако вокруг 120 тысяч. Это
две качественно разные группы, поэтому добавлен бинарный признак «баланс
не пуст».

**Три столбца выброшены**, причины разные: `RowNumber` и `CustomerId` —
идентификаторы, уникальные по строкам, обобщать по ним нечего; `Surname` —
2932 уникальных значения на 6000 обучающих объектов, и, что важнее, фамилия
в банковской модели работает прокси национальности, из-за чего банк начал бы
по-разному обращаться с клиентами по признаку, к их поведению не
относящемуся.

## Что сделано

1. **Данные разделены на три части 60/20/20** со стратификацией по целевому
   признаку. Доли ушедших по выборкам: 0,2038 / 0,2035 / 0,2035.
2. **Вся предобработка вынесена в `Pipeline`** — заполнение пропусков,
   масштабирование, one-hot кодирование. Статистики (медиана, среднее,
   дисперсия, набор категорий) обучаются только на обучающей выборке, поэтому
   утечка через предобработку исключена конструктивно.
3. **Базовые уровни посчитаны до обучения моделей** — в трёх вариантах,
   потому что при перекосе классов выбор варианта меняет планку в разы.
4. **Модели обучены сначала без учёта дисбаланса**, затем гиперпараметры
   подобраны по валидации, затем отдельно выбрана рабочая точка.
5. **Тестовая выборка использована один раз**, с порогом, зафиксированным
   по валидации.

## Результаты

### Базовые уровни (валидация)

| модель | accuracy | F1 | precision | recall |
|---|---:|---:|---:|---:|
| всем «останется» | 0,7965 | 0,000 | не определена | 0,000 |
| случайно, с сохранением долей | 0,6825 | 0,228 | 0,226 | 0,231 |
| **всем «уйдёт»** | 0,2035 | **0,338** | 0,2035 | 1,000 |

Планка по F1 — **0,338**, а не ноль. Константа «все уйдут» получает
precision, равный доле класса, и recall 1,0; их гармоническое среднее — треть.
Модель с F1 = 0,30 была бы хуже полного отсутствия модели.

Здесь же видно, почему accuracy для этой задачи непригодна: 0,7965 получает
модель, не нашедшая **ни одного** уходящего клиента.

### Модели без учёта дисбаланса (валидация)

| модель | F1 | AUC-ROC | PR-AUC | precision | recall |
|---|---:|---:|---:|---:|---:|
| логистическая регрессия | 0,501 | 0,831 | 0,614 | 0,722 | 0,383 |
| решающее дерево, без ограничения глубины | 0,496 | 0,684 | 0,349 | 0,496 | 0,496 |

F1 у моделей практически одинаковый, а AUC-ROC различается на 0,15. F1
измерен в одной точке (порог 0,5), AUC-ROC — по всем порогам сразу: логистическая
регрессия **ранжирует клиентов по риску существенно лучше**, и у неё есть
запас, который достаётся сдвигом порога. У дерева без ограничения глубины
листья почти чистые, предсказанные вероятности прижаты к 0 и 1, упорядочивать
ими нечего.

### Балансировка классов

`class_weight='balanced'`, те же модели:

| модель | F1 | AUC-ROC | PR-AUC |
|---|---:|---:|---:|
| логистическая регрессия | 0,501 → **0,568** | 0,831 → 0,834 | 0,614 → 0,608 |
| решающее дерево | 0,570 → 0,565 | 0,817 → 0,803 | 0,602 → 0,603 |
| случайный лес | 0,571 → **0,606** | 0,858 → 0,857 | 0,697 → 0,678 |

F1 растёт, AUC-ROC не меняется, PR-AUC даже слегка падает; precision
обменивается на recall (у леса 0,80 → 0,54 и 0,44 → 0,69). Балансировка
**не улучшила модели — она сместила рабочую точку**.

### Подбор модели и рабочей точки

Гиперпараметры леса подобраны по PR-AUC (сетка 5 × 10), затем для лучших
конфигураций найден порог, максимизирующий F1:

| модель | порог | F1 | precision | recall | PR-AUC |
|---|---:|---:|---:|---:|---:|
| лес 50/6 | 0,32 | 0,644 | 0,692 | 0,602 | 0,711 |
| **лес 40/6** | **0,31** | **0,641** | 0,673 | 0,612 | 0,710 |
| лес 50/8 | 0,29 | 0,639 | 0,602 | 0,681 | 0,709 |
| лес 50/7 | 0,31 | 0,638 | 0,655 | 0,622 | 0,709 |
| лес 40/7 | 0,27 | 0,633 | 0,586 | 0,688 | 0,708 |
| лес 20/9 — лучший по F1 при пороге 0,5 | 0,31 | 0,627 | 0,611 | 0,644 | 0,697 |

Все модели, отобранные по PR-AUC, обошли ту, что выигрывала по F1 при
стандартном пороге. Итоговая модель — **лес из 40 деревьев глубины 6 без
балансировки, порог 0,31**: из группы неразличимых результатов выбрана
простейшая конфигурация, а не формальный максимум.

### Тестовая выборка, один замер

| | F1 | AUC-ROC | PR-AUC | precision | recall |
|---|---:|---:|---:|---:|---:|
| валидация | 0,641 | — | 0,710 | 0,673 | 0,612 |
| **тест** | **0,644** | 0,867 | 0,681 | 0,676 | 0,614 |

Требование 0,59 выполнено. Валидационная и тестовая оценки совпали до
третьего знака по трём метрикам одновременно.

## Выводы

**Метрика без базового уровня не читается.** При перекосе 20/80 accuracy
награждает модель за полную бесполезность, а F1 имеет ненулевую планку: 0,338
даёт константа «все уйдут». Любое значение метрики интерпретируется только
относительно этих чисел.

**Критерий отбора модели должен совпадать с метрикой, которую докладываешь,
измеренной в той рабочей точке, которую действительно будешь использовать.**
Порог — свободный параметр, поэтому отбор по F1 при пороге 0,5 означает отбор
по случайной точке. Отбор по PR-AUC — отбор по качеству ранжирования, которое
порогом исправить нельзя. Разница не теоретическая: модель, выигравшая по F1
при пороге 0,5, после подбора порога оказалась последней из шести.

**Балансировка классов и сдвиг порога — один и тот же инструмент.** Проверено
с двух сторон: с `class_weight='balanced'` оптимальный порог уходит выше 0,5
(0,60–0,63), без него — ниже (0,27–0,32), а достигнутый максимум F1 в обоих
случаях один и тот же, 0,64. Поэтому в итоговой модели балансировки нет:
положение рабочей точки лучше задавать явно.

**Различия в третьем знаке — шум.** Пять лучших конфигураций уложились
в 0,004 при цене одного объекта 0,0005. Из них выбрана самая простая. Это
решение и объясняет, почему валидационная оценка сошлась с тестовой: по
валидации сделано больше пятисот замеров, и её максимум по построению
оптимистичен — но модель взята не с острого пика, а из плоского плато,
и порог тоже попал в широкий оптимум.

## Ограничения

- **Метрика задана условием задачи и для этого бизнес-процесса не оптимальна.**
  F1 взвешивает precision и recall одинаково, тогда как потерянный клиент
  стоит банку дороже одной лишней акции удержания. Корректнее была бы F-мера
  с весом в пользу recall.
- **Текущая рабочая точка смещена в сторону precision** (0,676 против 0,614),
  то есть в невыгодную для банка сторону. Порог стоит опустить ниже 0,31:
  F1 формально упадёт, потому что 0,31 — максимум именно F1, но потери банка
  уменьшатся.
- **Что метрики значат в деньгах.** Precision 0,676: из каждых 100 отмеченных
  клиентов 68 действительно уходят, 32 акции удержания потрачены на лояльных.
  Recall 0,614: модель находит 61% уходящих, остальные 39% уходят
  незамеченными.
- **Назвать оптимальную рабочую точку по этим данным нельзя.** Для этого нужны
  стоимость удержания одного клиента и его ожидаемая ценность — ни того, ни
  другого в датасете нет. Выбранный порог оптимален для F1, а не для прибыли.
- **Группа клиентов с четырьмя продуктами — 60 человек со 100% оттока.** На
  таком размере это не закономерность, а наблюдение; строить на нём выводы
  нельзя.
- **Модель обучена на одном историческом срезе** и не учитывает ни сезонности,
  ни изменений в продуктовой линейке банка. Перед внедрением нужна проверка
  на свежих данных.
